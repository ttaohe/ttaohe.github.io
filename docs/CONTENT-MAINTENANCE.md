# 内容维护

先说问题，再讲机制和证据。区分作者报告、个人设想与实际复现；性能结果保留硬件、负载、版本和统计口径。

文章以网页正文和图表自洽地讲清逻辑，必要的示例与实验解释直接放在文中。不再附 Markdown 原稿、全文包或实验代码包的下载入口，也不公开分发这些附件；私有内容主版本继续保留。

正文、图源在内容主仓库维护。主页只保存已确认的摘要快照；简历主版本在 resume-ng，PDF 同步到主页。草稿不进入公开快照。

| 配置 | 用途 |
| --- | --- |
| lib/blog/content.json | 标题、slug、日期、摘要、分类、标签及展示内容 |
| lib/blog/types.ts、schema.ts | 字段与兼容规则 |
| portfolio/research-progress.json | 研究主线与更新足迹 |

slug 尽量不变，迁移保留跳转。来源优先定位到论文版本或代码提交。摘要不能扩大原文结论；示意图与实测图须分清。

日报先在聊天中交付，同意后再归档发布。修订沿用原期次，不伪造更新时间，不恢复历史快照中的退役栏目。

更新足迹只记真实笔记进展。修订用 lastRevisedAt、progressSummary；日报和构建日期不代表个人研究成果。

发布后核对正文、目录、引用、图片和关联文章；改布局检查宽窄屏，改简历回读 PDF。历史交给 Git，不另存重复副本。
