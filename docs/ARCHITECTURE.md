## 为什么分成个人主页与阅读区域

第一次访问个人网站时，读者通常想迅速了解作者的背景、关注方向，以及可以从哪里开始阅读。个人主页因此以简介和经历为主，将最近的笔记、主题入口和简历放在容易找到的位置。

进入一篇技术文章之后，阅读需求会发生变化。长标题、代码、机制图和引用需要更宽松的排版，也需要稳定的目录和关联文章导航。研究站承担这部分阅读任务，个人主页则继续作为统一的介绍与入口。

这种分工允许两部分独立调整排版，同时通过明确的链接保持连贯。阅读者不需要关心页面由哪台服务器提供。

## 首页的阅读顺序

首页沿用代码编辑器的视觉语言：侧边栏对应章节，文件名提示内容类型，主区域承载正文。深色、浅色和柔和主题共用同一套内容结构；窄屏下，章节导航与正文改为适合纵向阅读的布局。

| 区域 | 回答的问题 |
| --- | --- |
| 个人简介与工作经历 | 作者是谁，主要关注哪些方向？ |
| 教育经历 | 作者的学习背景是什么？ |
| 项目经历区域 | 有哪些可以展开介绍的工作？当前保留空位 |
| 研究笔记与近期关注 | 可以从哪篇文章或哪个主题开始阅读？ |
| 简历 | 在哪里查看、下载独立的 PDF 版本？ |

主题切换和章节导航集中在 `portfolio/ui.mjs`。页面骨架与视觉样式分别保存在 HTML 和 CSS 中，修改文字时无需同时调整布局逻辑。

## 从材料到页面

一份材料在网站中可能有不同的表达形式。例如，文章正文适合保留为 Markdown，首页需要较短的标题、摘要与关键词，阅读页面还可能需要目录和图表元数据。

| 形式 | 用途 |
| --- | --- |
| 可编辑正文与图源 | 长期整理、审阅和修订 |
| 经确认的内容快照 | 为页面生成提供稳定输入，保留必要的展示字段 |
| 静态网页与资源 | 提供浏览器能够直接访问的发布结果 |

本仓库的 `lib/blog/` 保存首页生成所需的数据快照。`scripts/prepare-publish.mjs` 将它与主页模板、样式和资源组合起来，生成 `publish/`；`scripts/finalize-homepage.mjs` 再处理兼容链接并检查生成结果。

样式、脚本和简历等资源使用内容哈希命名。文件变化会生成新的资源地址，使新页面能够引用对应版本；稳定的资源别名则兼容已有链接。

## 源码分支与发布分支

`main` 保存可维护的源码与文档，`gh-pages` 保存面向浏览器的生成结果。源文件更新和页面发布是两个动作：这样可以先检查排版、链接和资料，再决定是否更新线上版本。

当前不依赖仓库工作流执行发布。GitHub Pages 使用发布分支中的静态文件，平台仍可能产生内置的 Pages 构建记录。仓库中保留的工作流文件属于历史实现，不是当前维护入口。

## 如何阅读保留的旧实现

早期研究站曾与个人主页共同构建，因此仓库中仍有 Next.js 页面、组件、内容格式及相关检查。它们有助于理解旧链接和历史数据，但当前首页的生成入口是 `portfolio/` 与两个页面生成脚本。

恢复旧页面或修改内容格式时，应先确认它是否仍在使用，再查看对应实现。旧代码中存在某个页面，并不表示该页面仍属于当前对外导航。项目、实验清单和管理后台目前不作为研究站的公开栏目。
